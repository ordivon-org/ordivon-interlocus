# Network → Interlocus Name Transition

## Decision

**Canonical project name:** Ordivon Interlocus
**Canonical referent:** Interlocus Capability
**Historical project name / compatibility alias:** Network

The transition changes the current descriptive language of the owner; it does **not** create a new semantic owner.

Stable owner identity remains:

- `research-owner:network`;
- `authority:ordivon:research-owner:network`;
- physical recovery root `owners/network/`.

These are durable identity/provenance locators, not the current human-facing project name.

## Why the old name became too narrow

The research lineage itself falsified communication/networking as the universal referent. NDF0 began with **Communicability**, but a Bell-pair / joint relational-resource counterexample showed that useful cross-locus capability can exist without the locally selectable information-bearing structure required by Communicability. NDF0 was therefore repaired and refrozen around **InterLocusCapability**, and NDF1 was correspondingly repaired from Communicability composition to Inter-Locus Capability Composition.

Subsequent derived theory widened the owner still further. The frozen structure `NCT_v1=<K,Π,H;J>_Γ` covers:

- capability–requirement contracts;
- grounded cross-locus projections;
- realization histories including establishment, store/carry, binding, forwarding specializations, branch/failover, retry/recovery, migration and reconciliation;
- typed currentness, identity, health, admission, reachability and serviceability judgements.

Conventional computer networking remains an important specialization and engineering realization family, but it no longer names the owner-level referent.

## Naming discipline after this transition

Use **Interlocus** for the project/owner in current prose.

Use **Interlocus Capability** for the canonical owner referent: the typed structure of capabilities that are required, offered, exposed, discovered, resolved, bound, composed, realized, observed, migrated, maintained and judged across distinct loci.

Use **network / networking** only when one of the following is intended:

1. historical Network-labelled research artifacts or task/ref identities;
2. conventional networking realizations such as packet/IP/routing/forwarding implementations;
3. an explicitly bounded network specialization of the broader Interlocus theory.

Do not use `Network` as a synonym for the whole current owner unless discussing historical naming.

## Frozen theory and identifier continuity

No frozen theory is rewritten merely to make the vocabulary look uniform.

The following remain immutable historical/canonical identifiers:

- NDF0–NDF5 and NDF6 NOT_ADMITTED standing;
- `NCT_v1` and the frozen artifact title `Network Core Theory v1`;
- `Network Capability Calculus v1`;
- `Network Projection & Currentness Theory v1`;
- `Network Operational Realization Theory v1`;
- Whole-NCT reconciliation artifacts;
- `refs/ordivon/research/network-*` refs;
- existing Host task identities and `result:network:*` references.

Current navigation may describe these as the frozen **Interlocus** core lineage while retaining the exact historical artifact names in parentheses or code formatting.

## Owner boundary

Interlocus owns qualified cross-locus capability relations and the Interlocus-specific laws of their contract structure, projection, composition, realization, discovery/resolution/binding, currentness and serviceability.

It does not annex:

- World substrate/physical truth;
- Runtime execution/attempt/effect truth;
- Harness Agent selection/invocation/control truth;
- Host continuity/organizational truth;
- SCD computational-description meaning;
- Computational Possibility regime-relative achievability;
- Normative permission, legitimacy, jurisdiction or normative power;
- generic mathematics, statistics, probability, information theory, control or security semantics.

## Transition law

`OwnerIdentityContinuity != NameContinuity`.

The same owner can acquire a better canonical name when research falsifies the old descriptive boundary. A name transition is admissible when it increases referent fidelity while preserving exact semantic lineage, frozen claims, negative history, authority identity and recovery.
